## Git Collaboration Rules

1. `main` contains only reviewed, stable versions.
2. Every member creates a feature branch from the latest `main`.
3. Direct development on `main` is prohibited.
4. Changes are merged through Pull Requests.
5. Every PR must describe changed files, experiment scope, tests, data-leakage implications, and whether the independent test set was accessed.
6. Raw data, generated datasets, model binaries, caches, credentials, and local environments must not be committed.
7. Formal metric files must be generated by code and must never be edited manually.
8. The independent test set may be opened only by the Project Lead after the experiment protocol, feature set, model settings, and threshold rule are frozen.

## Recommended Branches

- `integration/stage2`
- `feat/data-pipeline`
- `feat/logistic-regression`
- `feat/forest-models`
- `feat/xgboost`
- `feat/evaluation`

Before creating a branch, run `git switch main` and update it from `origin/main`. Keep each PR focused on one responsibility area and avoid committing generated outputs.
